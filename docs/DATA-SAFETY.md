# שמירת מידע: איך לא מאבדים נתונים

## איפה הנתונים
- קובץ אחד: `/data/planner.db` (SQLite). בו המשתמשים, הפרופילים, הימים (משימות, לו״ז, אוכל, צעדים, יומן), החברים והגלויות.
- `/data` הוא **נפח אחסון קבוע** של Fly בשם `dp_data` (מוגדר ב-`fly.toml`). הוא קיים בנפרד מהקוד ומהמכונה.

## מה פריסה עושה ומה היא לא עושה
- פריסה בונה תמונה חדשה של הקוד ומחליפה את המכונה. הנפח **מחובר מחדש כמו שהוא**, והנתונים נשארים.
- שום שלב בצינור לא מוחק נפח (אין `volumes destroy` בשום מקום). מחיקת נפח אפשרית רק בפקודה ידנית שלך.
- **שומר בצינור:** לפני כל פריסה נבדק ש-`fly.toml` עדיין מכיל `app = "dailyplanner"` ו-`source = "dp_data"` ו-`destination = "/data"`. אם מישהו (גם אני) משנה אחד מהם, הפריסה נעצרת. שינוי שם נפח או אפליקציה היה יוצר מסד ריק, והנתונים "נעלמים" מהאתר.
- המערכת רצה על **מכונה אחת בלבד** (`--ha=false`), כי SQLite לא מיועד לכמה שרתים שכותבים לאותו קובץ.
- **כלל מיגרציות:** שינוי מבנה המסד רק *מוסיף* (טבלה או עמודה חדשה, `CREATE TABLE IF NOT EXISTS` / `ADD COLUMN`). לא מוחקים עמודות ולא משנים משמעות. כך גם גרסה קודמת ממשיכה לעבוד אם צריך לחזור אחורה.

## גיבויים אוטומטיים (בתוך `/data/backups`)
| קידומת | מתי | כמה נשמרים |
|---|---|---|
| `boot-` | בכל הפעלת שרת שיש בה כבר נתונים, כלומר **לפני כל גרסה חדשה** ולפני כל שינוי סכמה | 8 אחרונים |
| `daily-` | פעם ב-24 שעות בזמן שהשרת רץ | 8 אחרונים |
| `manual-` | כשמריצים `node backup.mjs` | 8 אחרונים |
| `pre-restore-` | נשמר אוטומטית ממש לפני שחזור | 8 אחרונים |

הגיבוי נעשה בפקודת SQLite עקבית (`VACUUM INTO`), אז הוא תקין גם כשהשרת פעיל. אם גיבוי נכשל, השרת ממשיך לעבוד ורושם שגיאה ביומן.

**גיבוי נוסף של Fly:** מצלמת צילומי נפח אוטומטיים. לרשימה: `fly volumes snapshots list -a dailyplanner`. תקופת השמירה נקבעת על ידי Fly (בדקו בהגדרות שלה).

## מה שהגיבויים האלה לא מכסים
הגיבויים יושבים **על אותו נפח**. אם הנפח עצמו אובד, או שחשבון Fly נמחק, הם אובדים איתו. לכן:
- **פעם בחודש**: להוריד גיבוי למחשב.
  ```bash
  fly ssh console -a dailyplanner -C "node backup.mjs"
  fly ssh console -a dailyplanner -C "ls -1 /data/backups"
  fly ssh sftp get /data/backups/<שם-הקובץ-החדש-ביותר> ./planner-backup.db -a dailyplanner
  ```
- שמרו את הקובץ מחוץ ל-Fly (דיסק, ענן אישי). הקובץ מכיל מיילים ונתונים אישיים, אז טפלו בו בהתאם.

## שחזור מגיבוי
כשצריך לחזור למצב קודם (טעות, באג ב-migration, מחיקה בטעות):
1. לראות מה קיים: `fly ssh console -a dailyplanner -C "ls -1 /data/backups"`
2. לבחור קובץ ולהפעיל את השחזור (זה מפעיל מחדש את המכונה):
   ```bash
   fly secrets set RESTORE_FROM=boot-2026-10-05T17-03-41-025Z.db -a dailyplanner
   ```
3. לוודא ביומן: `fly logs -a dailyplanner` ← צריך להופיע "שוחזר מגיבוי".
4. **להסיר את המשתנה:** `fly secrets unset RESTORE_FROM -a dailyplanner`

מה נעשה בפועל: השרת בודק שהגיבוי תקין, שומר עותק של המצב *הנוכחי* כ-`pre-restore-*` (כדי שאפשר יהיה לבטל את השחזור), ורק אז מחליף. השחזור מתבצע **פעם אחת לכל קובץ** (סמן `.restored`), לכן שכחת להסיר את המשתנה לא תמחק נתונים חדשים בהפעלות הבאות. אם הקובץ לא נמצא, האתר ממשיך לעבוד עם המסד הנוכחי.
